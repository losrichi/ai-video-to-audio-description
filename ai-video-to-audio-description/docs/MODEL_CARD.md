# Model / system card

## System version
Video2Audio 1.0.0. Two explicitly separate backends: `shapes` and `blip`.

## `shapes` backend (fully tested, deterministic)
- **Type:** classical CV (HSV threshold, morphological cleaning, contour geometry, centroid differences) + template-based natural language generation.
- **Training:** none; not machine learning.
- **Input:** simple synthetic videos with saturated shapes on neutral backgrounds.
- **Capabilities:** detect a circle/triangle/square/rectangle, report red/blue/green/yellow and dominant first-to-last movement direction.
- **Out-of-scope:** human action understanding, objects in real footage, multi-object identity tracking, any safety-critical assistive interpretation.
- **Evaluation:** reproducible synthetic benchmark, metrics saved in the repo.

## `blip` backend (optional, integrated, not benchmarked)
- **Type:** pretrained vision-language model (`Salesforce/blip-image-captioning-base` via Hugging Face Transformers / PyTorch).
- **Training:** model pretrained by upstream authors; this project performs no training or fine-tuning.
- **Mechanism:** sample frames, invoke model per frame, deduplicate captions, attach optional visual-change note. Speech output is the same offline TTS system.
- **Requirements:** separate installation and first-time weights download, usually hundreds of megabytes. CPU may be slow; use a GPU if available.
- **Known limitations:** hallucinations, missed temporally brief events, biased or inaccurate descriptions, no synchronized time-level narration, generic-frame captions that may miss changes.
- **Evaluation status:** pretrained-weight inference not executed or scored in the published benchmark. A mocked adapter test checks API integration only.

## Text-to-speech
Offline eSpeak in the verified environment; fallback pyttsx3 if a system voice is available. Output is single WAV narration plus SRT frame-observation captions; the SRT is *not* claimed to synchronize the continuous narration.

## Risks, ethics and safe use
Autogenerated descriptions may be wrong. Do not use without human verification to guide people through physical spaces, convey critical emergency information, or replace professional accessibility review. Only process video you own or are authorized to process. Do not infer private or protected personal characteristics from videos.

## Next validation steps
1. Collect appropriately licensed real-world video clips with independently written human reference descriptions.
2. Execute the BLIP backend (preferably pinned to a recorded model revision) and log both successes and errors.
3. Have human reviewers rate factuality, temporal coherence, and usefulness; avoid treating BLEU/ROUGE as the sole quality metric.
4. Add timestamped narrations, interruption handling, voice options and multilingual support.
5. Conduct accessibility testing with consenting users and clearly report limitations.
